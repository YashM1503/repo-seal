# M1 controlled single-repository replay

## Outcome

M1 implements a controlled replay path for one generated Python repository with ten historical fixes. Every task is replayed twice at its base commit and twice at its accepted gold commit. The gate requires each base to fail, each gold snapshot to pass, and repeated verifier outputs to match exactly.

The suite emits a path-independent receipt with a stable SHA-256 digest. Tests build and replay the repository twice from fresh directories, compare the complete receipts, and compare the suite digest with a checked-in golden value. CI repeats the gate on Python 3.9, 3.11, and 3.13 in clean Ubuntu runners.

## Replay flow

```text
controlled Git repository
  -> git archive <base commit> -> candidate-base/ (no .git)
  -> git archive <gold commit> -> candidate-gold/ (no .git)

trusted verifier source
  -> copied read-only outside both candidate workspaces
  -> run twice against base
  -> run twice against gold

observations + immutable digests
  -> per-task ReplayReceipt
  -> ReplaySuiteReceipt
```

Archive extraction is implemented without `extractall`. Absolute paths, parent traversal, `.git` components, symlinks, hard links, and special files are rejected. Tree digests include relative paths, executable bits, and file bytes but exclude timestamps and temporary paths.

## Controlled history

The repository starts with ten intentionally broken functions and applies one deterministic fix per commit:

1. arithmetic addition;
2. inclusive clamping;
3. even-number detection;
4. slug normalization;
5. non-truncating mean;
6. order-preserving deduplication;
7. safe division;
8. whitespace-aware word counting;
9. path normalization;
10. Fibonacci calculation and negative-index rejection.

Commit authors, timestamps, messages, line endings, and source ordering are fixed so commit IDs and receipt digests can be reproduced.

## Run locally

```bash
PYTHONPATH=src python -m repolab_reference controlled-replay /tmp/repolab-controlled-replay
```

The destination must not already exist. The command creates:

- `repository/` — the controlled Git history;
- `trusted/` — the verifier source supplied to the orchestrator;
- `replay/` — source-only base/gold workspaces and staged read-only verifiers;
- `receipt.json` — the deterministic suite receipt.

## Gate assertions

For all ten tasks:

- base verification fails on every repetition;
- gold verification passes on every repetition;
- stdout/stderr digests and details are stable;
- snapshots contain only tracked source, never `.git`;
- verifier material is outside candidate workspaces;
- the staged verifier has no write bits and retains its digest;
- receipts contain no temporary filesystem paths;
- adjacent gold/base snapshot digests form one continuous commit chain.

## Explicitly unmeasured

M1 does not silently convert unimplemented collectors into passing evidence. Every receipt lists these unmeasured M0 checks:

- `ORACLE_EXPOSED` beyond structural verifier separation;
- `NETWORK_POLICY_FAILURE`;
- `GRADER_TAMPER_SURFACE` beyond read-only/digest checks;
- `SPEC_TEST_MISMATCH`;
- `OVERCONSTRAINED_TEST`;
- `UNDERPOWERED_TEST`;
- `CACHE_LEAK`.

These require stronger isolation, active probes, mutation fixtures, or human semantic review.

## Security boundary

The candidate code is generated by this repository and is trusted test material. Python isolated mode and a sanitized environment improve reproducibility; they are not a sandbox. Do not point this runner at arbitrary repositories or agent-generated patches.

M2 may add one agent adapter only after an independently reviewed execution boundary exists. The verifier must remain separate, provider credentials must never enter verification, and the unmeasured checks above must remain visible.
